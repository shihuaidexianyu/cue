# 146. watcher 死亡改为有界退避重生

§138 记录在案的限制「watcher 死亡 → 重爬但**不重生**,留给
下次进程启动」对常驻进程是真实缺陷:sakana 的目标形态是数周
不重启,睡眠唤醒/网络盘闪断/杀软干扰杀死句柄后,该根的实时
更新会静默陈旧到用户重启进程。**改为同线程有界重生**:

```text
死亡(打不开 / 读失败)→ 照发 WatcherDied(索引线程仍全量
  重爬补齐缺口,§138 语义不变)
  → 按 WATCHER_RESPAWN_DELAYS = [10s, 60s, 300s] 退避后
    在同一线程内重开句柄(不换线程,join/done 语义不变)
  → 任何一次成功的读取周期把连续死亡计数清零
  → 表尽(连续第 4 次死亡)→ 永久放弃 + Warn 日志(原行为)
```

设计边界:

- **有界**:不无限重试——永久坏根(被删的 index_dirs)每次死亡
  都伴一次全量重爬(实测 ~20 s),退避表 + 连续计数封顶把代价
  压到「三次重开后沉默」,瞬时抖动则永远能在 10 s 内恢复。
- **可中断**:退避睡眠每 200 ms 探一次 stop,退出 join 的 2 s
  上限(§142)不受威胁;睡死仍由 detach 兜底。
- **不动的部分**:溢出(Overflow)继续「重爬不杀句柄」;死亡
  上报与全量重爬的耦合不变;spawn_watchers / 就绪握手 / 退出
  join 全部不变——重生只是 watch_root 内部从「单次尝试」变成
  「尝试循环」。

## 验证

```text
单测 = 退避表金样(0/1/2 → 10/60/300 s,3+ → None);
     stop 预置时 300 s 睡眠亚秒返回;
     坏根(不存在的路径)直调 watch_root:WatcherDied 亚秒上报、
     stop 后线程干净退出(无第二次上报,join < 5 s)
回归 = 既有 26 个 file 模块测试(含真实 watcher 的增删改追踪、
     退出停机)原样通过
```
