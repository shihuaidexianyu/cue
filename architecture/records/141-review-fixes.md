# 141. 代码审查修正

本节修订 §30、§50、§54、§112、§128、§138、§140 的对应实现约定。

## 文件索引与生命周期

- 首爬与增量事件统一遵守目录剪枝:目录被排除时,后代文件事件也不得进入索引。纯噪声批次不重建快照。
- 索引线程保存当前快照使用的 `(fragments, exclude_noise)`;即使其他线程已经读取新名单,策略差异仍触发全量重建。
- 名单读取在后台串行进行,避免旧读取覆盖新版本。无语义变化和解析失败不主动请求重建。
- 文件事件队列容量为 4096。满时合并成一个 overflow 标记,消费者通过全量扫描恢复,不阻塞 watcher、不无限积压。
- watcher 使用 overlapped `ReadDirectoryChangesW`,首次读取投递成功后才开始首爬。停止时取消 IO,等待完成后才释放缓冲区和句柄。
- 索引遍历检查停止标记。`unload` 与最后一个索引句柄释放会停止并回收线程;停止也唤醒首爬等待者。
- 根目录 watcher 的致命错误仍记录日志并重扫一次,自动重新连接不在此次修改范围。

## 启动身份与路由

Win32 应用身份保留原始参数的大小写、空白与引号,并区分工作目录。路径部分仍按 Windows 常见的不区分大小写语义归一。不能把任意程序参数当作不区分大小写的文本进行去重。

未指定工作目录且原参数本来就符合旧归一结果的入口保留原 usage key。受身份修正影响的入口会使用新的统计键;旧记录留在 usage 文件中,不把原先可能混合的统计强行归到某个新入口。

触发词采用最长有效匹配。字母/数字结尾仍要求词边界,完全相同的触发词仍拒绝提交。

## 焦点与剪贴板

Host 同时发送 FocusLost 和 FocusGained,由 Core 同步 toggle 所依据的焦点状态。

复制操作先准备 Unicode 全局内存,再用同线程的 message-only 窗口作为 clipboard owner。所有失败路径通过 RAII 释放本地资源,成功后才把内存所有权交给系统。

真实剪贴板集成测试在独立子进程的私有非交互 window station 中执行,不操作用户剪贴板。测试默认忽略,因为部分 Windows 环境禁止创建 window station;准备内存与 owner 生命周期测试默认运行。

## Usage 写入与退出

Usage 的内存提交立即完成。容量为 1 的通知队列合并写请求,专属线程串行快照、序列化并执行 tmp + rename。普通激活不等待磁盘,正常退出显式 flush。

退出路径改为 `Host QuitRequested → Core 停止模块并 flush → QuitApplication effect → 平台退出`。进程被强杀或断电时可能丢失最后尚未落盘的一批使用统计,已有文件仍通过临时文件替换避免半截写入。

## 类型化设置与架构护栏

`SettingKind::Integer` 携带范围,`SettingKind::Enum` 携带稳定值与显示标签。Core、持久化读取与 UI 共用规格:整数行支持文本编辑与错误提示,枚举行使用中文标签并由 Enter/左右键循环选择。

旧 TSV 编码保持兼容。非法持久化值逐项回落,不能因为阈值损坏而把用户已经关闭的锁键服务重新打开。

依赖方向护栏使用 `cargo metadata --no-deps --locked` 解析真实 package 名,覆盖 workspace 引用、依赖别名和 TOML 表格形式,不再依赖模块名前缀正则。脚本内保留允许/禁止依赖的回归用例。
